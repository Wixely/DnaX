# DNA X 10.0.0-alpha.6

This prerelease adds **DnaX.Uploads**, an experimental library for browser-owned uploads that can continue independently of a Blazor Server circuit.

## Resilient uploads prototype

- Multiple-file queues with per-file progress, pause, cancellation and retry controls.
- Developer-owned profiles for chunking, resumability, automatic retries, browser persistence, concurrency and file-size limits.
- Whole-file HTTP streaming when chunking is disabled; bounded chunks and committed-offset recovery when enabled.
- Authenticated endpoints with antiforgery validation, owner isolation, idempotent session creation and durable transport receipts.
- A single-process disk store with interrupted-write rollback and journal-based restart recovery.
- Size-bounded browser file persistence and verified reselection of larger files after reload.
- A Blazor sample, VS Code debug configuration and reproducible browser test scenarios.

The package has no third-party package dependencies and uses the ASP.NET Core shared framework. Install `DnaX.Uploads` version `10.0.0-alpha.6` from the Wixely GitHub Packages feed. See [integration and run instructions](https://github.com/Wixely/DnaX/blob/v10.0.0-alpha.6/docs/uploads-prototype.md).

**Experimental limitations:** the upload API, protocol and journal format are not stable. This is a custom prototype transport, not a tus implementation. Completion means transport bytes were accepted, not that application validation or business processing finished. The store is single-process and uses absolute session expiry. Physical mobile picker tests and actual 50/100 GiB transfers remain outstanding. Configurable large-file limits and bounded streaming tests are not a claim of verified massive-file performance.

## Other changes since the last GitHub release (alpha.3)

- Added MCPFab abstractions, host composition and build-time policy support for MCP servers, including trim-safe JSON helpers, a trim smoke sample and shared server release infrastructure.
- Refined MCPFab policy tiers and added host favicon/console branding support.
- Normalized migration checksum line endings for consistent behavior across platforms.

All packable projects now use version `10.0.0-alpha.6`. Keep related DnaX package references aligned. Existing applications do not acquire the uploads package unless they explicitly reference it. The upload sample's automatic local demonstration identity is not a production authentication setup.

## Verification

Local Windows verification includes a Release build, automated upload tests and Chromium scenarios covering circuit disconnect, a lost accepted-chunk response, full reload recovery and rejection of a mismatched reselected file. The release workflow also requires the full Windows/Linux build, formatting, test, trim smoke and package-isolation checks before publishing packages and this release.

Release assets contain NuGet packages. Debug symbols and development build artifacts are not included in the release assets.
